# 가정 실험실 설계 문서

- 작성일: 2026-10-13
- 상태: 설계 초안 (사용자 검토 대기)

## 1. 의도

사용자는 "로또 확률 자체는 변하지 않지만, 가정을 세우고 그 가정 아래에서 계산하면 확률을 높여 볼 수 있다"는
생각에서 출발했다. 예시는 둘이다.

- 과거에 나온 1등 조합을 빼고 남은 조합 안에서 고르면 확률이 어떻게 되는가.
- 그렇게 남은 것 가운데 자주 나온 번호로만 고르면 확률이 어떻게 되는가.

이 기능은 그 가정을 직접 걸어 보는 화면이다. 다만 화면은 **가정 확률만 보여 주지 않는다.** 가정이 참이라고 칠 때의
확률, 그 가정이 과거에 실제로 맞았던 비율, 그리고 변하지 않는 실제 확률을 언제나 나란히 적는다. 사용자는 이것이
옳은 표현 방식이라고 정했다.

세 숫자는 이렇게 이어진다.

```
가정 적중률 × 가정 확률 ≈ 실제 확률 (1 / 8,145,060)
```

가정이 좁을수록 가정 확률은 커지고, 가정 적중률은 그만큼 작아진다. 이 관계가 화면에 그대로 드러나므로 가정 놀이가
사용자를 속이지 않는다.

여기에 Claude 의 추천안 두 개를 함께 넣는다. 사용자가 함께 진행하기로 했다.

- **가정 백테스트**: 그 가정으로 과거 회차를 돌렸다면 등수별로 몇 번 맞았을지를, 같은 수의 무작위 픽과 나란히 보여 준다.
- **인기 조합 회피**: 많은 사람이 고르는 경향이 있는 패턴을 알려 준다. 당첨 확률은 바뀌지 않지만, 당첨됐을 때
  나눠 가질 사람이 적어질 수 있다. 수학적으로 실제 이득이 있는 거의 유일한 방향이다.

## 2. 목표, 비목표, 반목표

목표:

- 가정 두 개를 켜고 끌 수 있다: 과거 1등 조합 제외, 자주 나온 번호 K개 안에서만 고르기.
- 걸린 가정마다 가정 확률, 가정 적중률, 실제 확률 셋을 보여 준다.
- 걸린 가정으로 과거 회차를 백테스트해 무작위 픽과 비교한다.
- 걸린 가정으로 번호 6개를 뽑아 현재 조합으로 넘긴다.
- 현재 조합에 인기 패턴이 있으면 경고한다.

비목표 (이번 범위 밖):

- 이 두 가정 말고 다른 가정. 범위는 지금까지 대화에서 나온 것으로 확정했다.
- 사용자가 가정을 자유롭게 조립하는 규칙 편집기.
- 실제 구매자 분포 데이터에 근거한 인기도 점수. 그런 데이터가 없다.

반목표 (기술적으로 돌아가도 이렇게 되면 실패다):

- 가정 확률이 실제 확률이나 가정 적중률 없이 혼자 화면에 나온다.
- "당첨 확률이 올라갑니다", "당첨 확률 N배" 같은 문구가 나온다. 가정 확률은 언제나 「가정 확률」이라는 이름으로만 부른다.
- 가정 적중률을 계산할 때 그 회차 이후의 데이터를 쓴다(미래 정보 누설). 그러면 적중률이 실제보다 좋아 보인다.

## 3. 원칙 문구 개정

v1 설계의 원칙 「과거 통계는 미래 당첨 확률을 높이지 못한다」는 사실로서 그대로 둔다. 다만 「예측력을 주장하지 않는다」를
화면에 가정 확률을 아예 내지 않는다는 뜻으로 읽으면 이 기능과 부딪힌다. 그래서 이번 작업에서 아래 두 자리에 한 줄을 더한다.

- [v1 설계 §1 제품 개요](<2026-06-04-fortuna-lottery-design.md#1-제품-개요>)의 핵심 설계 원칙과
  [§10 정직성 장치](<2026-06-04-fortuna-lottery-design.md#10-정직성-장치-신뢰-확보>)
- 저장소 루트 `CLAUDE.md` 의 「이 저장소는 무엇인가」

더할 문장은 이것이다.

> 가정 기반 기능은 가정 확률을 보여 줄 수 있다. 그때는 언제나 실제 확률 1/8,145,060 과 그 가정의 과거 적중률을 함께 적는다.

## 4. 계산 정의

전체 조합 수 `T = 8,145,060` 은 커널의 `TOTAL_COMBINATIONS` 를 쓴다.

### 4.1 가정 A — 과거 1등 조합 제외

- 제외 집합: 지금까지 나온 1등 조합(본 번호 6개)의 서로 다른 것들. 개수를 `P` 라 한다.
- 가정 우주: `T − P` 개.
- 가정 확률: `1 / (T − P)`.
- 가정 적중률: 각 회차 r 의 1등 조합이 r 보다 앞선 회차들의 1등 조합과 겹치지 않았던 비율.
  지금까지 같은 1등 조합이 다시 나온 적이 없으므로 100% 에 가깝게 나온다. 화면은 이 사실을 그대로 보여 준다.
- 워밍업은 4.2 와 같다(앞선 회차 100 개 미만은 세지 않는다). 그래야 스위치를 바꿔도 센 회차 수가 같아 세 숫자를 견줄 수 있다.

### 4.2 가정 B — 자주 나온 번호 K개 안에서

- 풀: 출현 횟수 상위 K개 번호. 횟수가 같으면 작은 번호를 먼저 넣는다. K 는 6~45 의 정수다. K = 45 는 가정을 끈 것과 같다.
- 가정 우주: `C(K, 6)` 개.
- 가정 확률: `1 / C(K, 6)`.
- 가정 적중률: **회차를 앞에서부터 걸으며** 계산한다. 회차 r 의 풀은 r 보다 앞선 회차만으로 만든다. 그 회차의 본 번호 6개가
  모두 풀 안에 들었으면 적중이다. 앞선 회차가 100 개 미만인 회차는 세지 않는다(풀이 안정되기 전이라서다).
- 비교값: 무작위라면 기대되는 적중률 `C(K, 6) / T` 를 같이 보여 준다. 관측 적중률이 이 값과 비슷하면 「자주 나온 번호」가
  다음 회차에 대해 아무것도 알려 주지 않았다는 뜻이다.

### 4.3 두 가정을 함께 걸 때

- 가정 우주: `C(K, 6) − (풀 안에 완전히 들어가는 과거 1등 조합 수)`.
- 가정 적중률: 두 조건을 모두 만족한 회차의 비율. 회차 r 에서 쓰는 풀과 제외 집합은 r 보다 앞선 회차로만 만든다.

### 4.4 가정 백테스트

- 4.2 와 같은 걸음으로 회차를 앞에서부터 걷는다(앞선 회차 100 개 미만은 건너뛴다).
- 회차마다 가정 아래에서 픽 20 장, 아무 가정 없는 무작위 픽 20 장을 뽑아 커널의 `scoreAgainstDraw` 로 채점한다.
- 난수는 고정 시드의 `mulberry32` 다. 같은 데이터와 같은 가정이면 결과가 언제나 같다.
- 결과: 가정 쪽과 무작위 쪽의 총 장수와 등수별 횟수.
- 1등은 이 장수로는 사실상 나오지 않는다. 화면은 1등 칸 대신 4.1~4.3 의 세 확률을 가리킨다.

### 4.5 가정으로 번호 뽑기

- 가정 B 가 걸리면 지금 데이터 전체로 만든 풀 안에서, 아니면 1~45 에서 6개를 무작위로 뽑는다.
- 가정 A 가 걸리면 뽑은 조합이 과거 1등 조합과 같을 때 다시 뽑는다.

### 4.6 인기 조합 패턴

현재 조합에서 아래 패턴을 찾는다. 이 목록은 사람들이 흔히 고른다고 알려진 경향에 기댄 것이고, 실제 구매 데이터로 잰 것이
아니다. 화면은 그 사실을 적는다.

- 모든 번호가 1~31 안에 있다(생일 숫자).
- 연속된 번호가 3개 이상 이어진다.
- 6개가 등차수열을 이룬다.
- 과거 1등 조합과 똑같다.

경고 문구는 「당첨 확률은 같지만, 당첨되면 나눠 가질 사람이 많을 수 있습니다」의 뜻을 담는다.

## 5. 구조

배치와 계층은 저장소 `CLAUDE.md` 와 vault 골조 문서가 정한 대로 따른다. 여기서는 새로 생기는 자리만 적는다.

- 계약: `packages/contract/src/hypothesis/` 에 스키마를 둔다.
- 서버: `apps/api/src/modules/hypothesis/` 새 모듈. 과거 회차는 자기 `DrawHistoryPort` 로 받고,
  `CompositionModule` 이 `LotterietusFacade` 를 꽂는다(simulation 과 같은 방식).
- 조합 뽑기: 지금 `generator/business/generate.ts` 에 있는 뽑기를 `packages/kernel` 로 옮겨 두 모듈이 함께 쓴다.
  모듈 사이 import 는 금지이고, 여러 모듈이 쓰는 순수 로직은 커널에 둔다는 규칙을 따른 것이다.
- 화면: `apps/web/src/modules/hypothesis/` 새 모듈과 홈의 새 탭 「가정 실험실」(키 `hypothesis`).
  뽑은 번호는 생성기와 같은 방식으로 셸의 현재 조합에 넘긴다.

엔드포인트는 셋이다(전역 접두 `/api`).

- `POST /api/hypothesis/evaluate`: 요청 `{ excludePastWinners: boolean, topK?: number }`.
  응답에 실제 확률 분모, 가정 우주 크기, 가정 적중률(적중 회차 수, 센 회차 수, 무작위 기대 적중률), 백테스트 결과, 지금 풀을 담는다.
- `POST /api/hypothesis/generate`: 요청은 evaluate 와 같다. 응답은 번호 6개.
- `POST /api/hypothesis/popularity`: 요청 `{ numbers }`. 응답은 걸린 패턴 목록.

## 6. 화면

「가정 실험실」 탭 하나에 위에서 아래로 놓는다.

1. 가정 스위치: 「과거 1등 조합 제외」 켜기/끄기, 「자주 나온 번호 K개 안에서」 켜기/끄기와 K 값.
2. 세 확률: 가정 확률, 가정 적중률(무작위 기대값과 함께), 실제 확률. 셋은 같은 크기로 나란히 놓는다.
   가정 확률만 크게 강조하지 않는다.
3. 백테스트 비교: 가정 쪽과 무작위 쪽의 등수별 횟수.
4. 「이 가정으로 번호 뽑기」 버튼과 지금 풀의 번호.
5. 현재 조합의 인기 패턴 경고.

## 7. 정해 둔 것 중 Claude 의 판단

아래는 사용자가 정하지 않았고 Claude 가 정했다. 다르게 원하면 고친다.

- K 의 기본값은 20 이다.
- 적중률과 백테스트의 워밍업은 앞선 회차 100 개이고, 어느 가정을 걸든 똑같이 적용한다.
- 백테스트는 회차마다 가정 쪽 20 장, 무작위 쪽 20 장이다.
- 출현 횟수가 같으면 작은 번호를 풀에 먼저 넣는다.
- 인기 패턴 네 가지의 목록.
- 화면은 탭 하나로 둔다. 기존 시뮬레이션 탭과 합치지 않는다.

## 8. 짓는 쪽에 맡기는 것

- 스위치와 K 입력의 컴포넌트 모양.
